## In the browser

The [flasher](/flash/) writes the latest stable [release](/docs/updates#releases). It needs Chrome or Edge on a computer.

<Ports />

| Mode | What it does |
|---|---|
| **Full install** | Erases everything and starts with default settings. For a new board, or one that ran other firmware |
| **Update** | Writes only the firmware. Settings, paired hosts and API keys stay |

After flashing, the flasher can set Wi-Fi, the admin password and the name over the same cable. Or skip it and use the [web setup](/docs/first-setup). Over USB the board takes these only until setup is done, and in the first 5 minutes after each start.

The flasher writes only the main chip. The Wi-Fi chip gets its firmware as a normal [update](/docs/updates).

Something went wrong? See [Flashing problems](/docs/flash-troubleshooting).

## With esptool

Use [esptool](https://docs.espressif.com/projects/esptool/) 5 or newer with the files from a [release](/docs/updates#releases).

<Tabs items={['Full install', 'Update']}>
<Tab value="Full install">

```bash
esptool --chip esp32p4 -p /dev/ttyACM0 erase-flash
esptool --chip esp32p4 -p /dev/ttyACM0 -b 921600 write-flash 0x0 deckconnector-factory.bin
```

</Tab>
<Tab value="Update">

```bash
esptool --chip esp32p4 -p /dev/ttyACM0 -b 921600 write-flash 0xf000 ota_data_initial.bin 0x20000 deckconnector.bin
```

</Tab>
</Tabs>

On Windows the port is `COM3` or similar, on macOS `/dev/cu.*`.

## From source

Needs ESP-IDF 6.0.2, Node.js and [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/FusselTV/deck-connector.git
```

```bash
cd deck-connector/web && npm ci && npm run build
cd ../tools && uv run python -m dbtools.dbfw keygen
cd ../firmware && idf.py build && idf.py -p /dev/ttyACM0 flash
```

The web UI is part of the firmware, so it builds first. `keygen` makes your own update key once. A board takes only updates signed with the key its firmware was built with.
