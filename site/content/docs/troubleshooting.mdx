Flashing fails? See [Flashing problems](/docs/flash-troubleshooting).

## The deck screens

| On the deck | Meaning and fix |
|---|---|
| **Kein Netz** (no network) | Neither LAN nor Wi-Fi has an address. Plug in a cable, or start **Setup-WLAN** in the menu |
| **Warte auf Companion** | Companion is chosen but not connected. See [below](#companion-does-not-connect) |
| **Warte auf die Elgato App** | The Elgato app is chosen but not connected. See [below](#the-elgato-app-does-not-find-the-deck) |
| **Suche Server** | No server URL set, and none announces itself. Add one under **Sources** |
| **Server getrennt** | The server does not answer. Check that it runs, and the URL and port |
| **Verbindungsanfrage** | An unknown computer wants the deck. **Annehmen** lets it in, **Ablehnen** keeps it out |
| **Companion gefunden** | Companion announces Satellite. **Verbinden** connects, **Nein** stops asking |
| **Setup 2/5** | Someone runs the web wizard. Finish or skip it in the browser |

## The deck stays dark or is slow

- The board needs power. With PoE, the switch port must deliver it.
- The deck goes into the **USB-A** port.
- **Reconnect deck** in the web UI turns its USB power off and on.
- Behind a USB hub the deck may run at full speed, and pictures come slower. Plug it in directly.

## The web UI does not open

- Use the IP from the deck menu instead of the `.local` name.
- With **HTTPS only** on, use `https://`.
- After a network change the address changes. The deck menu shows the new one.
- After too many wrong passwords, the login waits up to a minute.
- [Lost the password?](/docs/security#lost-password)

## Companion does not connect

- **Settings › Satellite** must be on in Companion.
- The board must reach Companion on TCP 16622, or 16623 for `ws://`. In Docker, publish that port and enter the address by hand.
- **Check** next to the address under **Sources** shows whether Companion answers.
- The deck shows up twice? A proxy hides Companion's address. Remove the remote surface in Companion.

## The Elgato app does not find the deck

- The computer must be in the same network, not a guest Wi-Fi.
- A firewall on the computer may block the app.
- The deck must be plugged in. A dock without a deck is ignored until the app restarts.
- A denied app asks again only after it restarts.

## An update does not stay

The new firmware did not reach the network within two minutes, or did not stay up for 20 seconds. **Diagnostics › Log › Before the last restart** shows why ([demo](/demo/#diagnose)).

## Logs and crash reports

**Diagnostics** has the log, events, inputs and the last crash report. The log of the start before stays until a power cut. A crash report can hold the password, so only the password opens it.

```bash
curl -u admin:PASSWORD http://192.168.1.50/api/log > log.txt
curl -u admin:PASSWORD 'http://192.168.1.50/api/log?boot=prev' > log-prev.txt
```
