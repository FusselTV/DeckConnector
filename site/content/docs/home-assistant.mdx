The DeckConnector integration brings the board and every deck on it into [Home Assistant](https://www.home-assistant.io/). Each press, release, dial turn and touch arrives at once and can start an automation. You set the brightness, turn the screens off, pick the host and see what each deck shows.

## Install

Open **Settings › Marketplace**, choose **Add from link** and paste this address. Before Home Assistant 2026.11, add it in HACS under **Custom repositories** as an **Integration**.

```text
https://github.com/FusselTV/DeckConnector
```

Download **DeckConnector**, then restart Home Assistant.

## Set up

Home Assistant finds the board by itself and offers it under **Settings › Devices & services**. If it does not, add **DeckConnector** there and enter the board's address.

Pick **Confirm on the deck**, or **Enter the web password** if no deck is attached. Home Assistant then makes its own [API key](/docs/security#api-keys) on the board.

<Shot src="ha-flow" alt="Pick how Home Assistant gets access: confirm on the deck or enter the web password" width={580} height={264} />

**Reconfigure** on the integration changes the board's address and keeps the key.

## What you get

The board is one device, and each deck is a device behind it. A deck you plug in later appears at once.

These start disabled. Turn them on under the device if you need them:

- **Wi-Fi signal**, **Wi-Fi network** and **Last restart** of the board.
- **Firmware** update. With it on, the board asks GitHub for new releases every 6 hours.
- **PIN lock** of a deck. It shows **Locked** while Companion locks the deck with its PIN. Its two triggers also show up as buttons in a HomeKit bridge.
- **Reconnect** of a deck. It turns the USB port off and on, for a deck that hangs.

**Volume** and **Find** exist only on a board with a speaker. **Screen off after** is in minutes, 0 means never.

The board pushes every change at once. Signal and temperature update once a minute.

## Automations

In the automation editor, pick **Device**, then the deck, then a trigger such as **Key 3 pressed**, **Dial 1 turned right** or **Touch strip swiped left**.

Every deck also has one **Controls** event entity for YAML and templates. Its `event_type` says what happened, for example `key_3_press`. A dial turn carries `ticks`, a touch carries `x` and `y`.

```yaml
triggers:
  - trigger: state
    entity_id: event.stream_deck_controls
    not_from: unavailable
    not_to: [unavailable, unknown]
conditions:
  - condition: state
    entity_id: event.stream_deck_controls
    attribute: event_type
    state: key_3_press
```

The host draws the keys. A key that Companion or the Elgato app also uses runs both actions.

**Dial dims a light.** Turn a dial right for brighter, left for darker. Press it to switch the light on or off.

## Apple Home

The [HomeKit Bridge](https://www.home-assistant.io/integrations/homekit/) shows a deck as a set of buttons in the Home app. Open the options of the HomeKit Bridge in bridge mode and pick the deck under **Devices (Triggers)**. Each key press, dial press, dial turn and touch is one button.

## Good to know

- Home Assistant talks to the board over plain HTTP on port 80.
- Presses from the web page or a script never reach Home Assistant. Home Assistant never presses anything on the deck.
- After a firmware update the integration loads again by itself, so new entities appear.
- The logger is `custom_components.deckconnector`.

## Troubleshooting

Problems that Home Assistant can see show up under **Settings › Repairs**: a board that allows HTTPS only, and decks that stay dark because of the deck limit.

If all entities are unavailable, Home Assistant cannot reach the board. Open the board's address in a browser. If the address changed, use **Reconfigure**.

For a bug report, use **Download diagnostics** on the board's device. It leaves out the key, addresses and serial numbers.

## Remove

Delete the integration under **Settings › Devices & services**. Then remove its key `home-assistant-xxxxxxxx` under **Access › API keys** on the board.
