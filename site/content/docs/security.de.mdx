## Passwort

Die Weboberfläche hat einen Benutzer, `admin`. Beim ersten Start erzeugt der Connector ein zufälliges Passwort und zeigt es im Deck-Menü. Ein eigenes (6 bis 23 Zeichen) setzt du in der Einrichtung oder unter **Zugang** ([Demo](/de/demo/#access)).

Vor der Einrichtung kommt jeder Browser, der den Connector öffnet, ohne Passwort hinein. Das geht in den 30 Minuten nach dem Start, bis ein Passwort gesetzt oder die Einrichtung fertig ist. Ein Werkszustand öffnet es wieder.

Ein neues Passwort startet den Connector neu und beendet jede Sitzung. Eine Sitzung endet nach 12 Stunden ohne Nutzung und bei einem Stromausfall.

## Passwort vergessen

Die Anmeldeseite bietet drei Wege. Für jeden muss jemand am Deck stehen, und Eingaben über die API zählen nie.

| Weg | Am Deck |
|---|---|
| Am Deck anfragen | Innerhalb von 60 s auf **Annehmen** tippen |
| Passwort am Deck | Das Passwort steht 30 s lang da |
| Zurücksetzen | Innerhalb von 60 s zweimal auf **Zurücksetzen** tippen. Alle Einstellungen sind weg |

Endet einer davon ohne **Annehmen**, kann dieselbe Adresse ihn erst nach einer Minute wieder starten. Die Anmeldeseite zeigt, wie lange. Eine IPv6-Adresse zählt nach ihrer ersten Hälfte (`/64`).

## Sperre

- Nach fünf falschen Passwörtern von einer Adresse wartet diese Adresse ein paar Sekunden, höchstens eine Minute.
- Nach 30 falschen Passwörtern in einer Minute von allen Adressen warten alle bis zum Ende der Minute, außer den letzten vier Adressen, die sich angemeldet haben.
- Ein API-Schlüssel wird nie gesperrt.

## API-Schlüssel

Skripte und [Home Assistant](/de/docs/home-assistant) nutzen einen API-Schlüssel. Du legst ihn unter **Zugang › API-Schlüssel** an. Er wird nur einmal angezeigt.

```bash
curl -H 'Authorization: Bearer SCHLUESSEL' http://192.168.1.50/api/status
```

Ein Schlüssel hat **Steuern** (`control`) oder **Vollzugriff** (`full`). Es gibt höchstens 8. Ein gelöschter gilt sofort nicht mehr. Ein neuer Schlüssel mit demselben Namen ersetzt den alten. Der Connector speichert nur einen Hash, und eine Sicherung enthält nie einen Schlüssel. Home Assistant löscht seinen eigenen Schlüssel, wenn du die Integration entfernst.

## HTTPS

Der Connector antwortet auf Port 80 und per HTTPS auf 443. Sein Zertifikat stammt von seiner eigenen CA, die er beim ersten Start anlegt. Vertraue der CA einmal auf jedem Gerät, unter **Zugang › HTTPS**. Dann warnt unter `https://<name>.local` kein Browser mehr.

- Die CA bürgt nur für `<name>.local` und `localhost`, nie für einen anderen Namen oder eine IP-Adresse.
- Das Zertifikat wird 30 Tage vor Ablauf erneuert. Der Fingerabdruck ändert sich dabei, die CA bleibt.
- Ein neuer Name bekommt eine neue CA. Vertraue ihr dann auf jedem Gerät neu.
- Ein Zurücksetzen auf Werkszustand löscht die CA.
- `GET /api/ca` liefert die CA, `GET /api/cert` das aktuelle Zertifikat als PEM.
- **Nur HTTPS** schaltet unverschlüsseltes HTTP ab. Seiten leiten um, API-Aufrufe über HTTP bekommen 403. Solange das Setup-WLAN offen ist, bleibt HTTP an.
- Du kannst ein eigenes Zertifikat mit Schlüssel als PEM hochladen. Einen Schlüssel mit Passwort lehnt der Connector ab.

## Passkeys

Mit einem Passkey meldest du dich per Fingerabdruck, Gesicht oder Geräte-PIN an. Du legst ihn unter **Zugang › Passkeys** an.

- Er braucht HTTPS ohne Warnung und einen Namen, etwa `https://deckconnector-a1b2c3.local`. Vertraue zuerst der CA oder lade ein Zertifikat für deinen eigenen Namen hoch.
- Ein Passkey gilt nur unter dem Namen, unter dem er angelegt wurde. Nach einer Umbenennung legst du ihn neu an.
- Höchstens 8 Passkeys. Das Passwort gilt weiter. Ein Zurücksetzen auf Werkszustand löscht alle Passkeys.

## Hinter einem Reverse Proxy

Ein Proxy wie Caddy kann den Connector unter seinem eigenen Namen ausliefern. Dann kommt jede Anfrage von der Adresse des Proxys. Trage diese Adresse unter **Zugang › HTTPS › Reverse Proxy** ein. Der Connector nimmt den Client dann aus dem letzten Eintrag von `X-Forwarded-For`. Er nutzt ihn für die Sperre, für Passkeys und für die Anmeldefrage auf dem Deck.

- Der Connector liest den Header nur von dieser einen Adresse. Von allen anderen ignoriert er ihn.
- Der Proxy muss den `Host`-Header behalten und den Client an `X-Forwarded-For` anhängen. Caddy macht beides von selbst.
- Durch den Proxy gehen die Einrichtung im ersten Browser und Companions Discover nicht.

## Setup-WLAN

Ein Browser im Setup-WLAN braucht kein Web-Passwort. Das WLAN-Passwort zeigt nur das Deck, zum Verbinden musst du also am Deck sein. Nur Handys im Setup-WLAN bekommen die Anmeldeseite und die DNS-Antworten des Connectors, Geräte im LAN nie.

## CORS

Eine Webseite von einem anderen Origin darf die API mit einem API-Schlüssel aufrufen, wenn ihr Origin unter **Erlaubte Webseiten** steht. Anfangs leer. Cookies gelten nie über Origins hinweg.
