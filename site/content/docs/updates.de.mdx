Die Platine nimmt signierte `.dbfw`-Dateien an. Jede Datei enthält einen Teil, und die Platine erkennt, welchen.

| Teil | Nach dem Update |
|---|---|
| Firmware | Kommt in den nächsten Platz, die Platine startet ihn |
| WLAN-Chip | Beide Chips starten neu |
| Weboberfläche | Sofort ausgeliefert |
| Bootloader, Partitionstabelle | An Ort und Stelle geschrieben, kein Neustart |

## Installieren

- In der Weboberfläche unter **Firmware** ([Demo](/de/demo/#firmware)) eine Datei wählen oder eine `http://`-URL angeben.
- Von deinem [eigenen Server](/de/docs/own-server) `{"t": "ota", "url": "http://..."}` schicken.
- Über die [API](/de/docs/api#firmware) `POST /api/ota` mit der Datei oder `POST /api/ota/url`.

## Prüfung und Rückfall

<OtaFlow lang="de" />

Eine Platine nimmt nur Dateien an, die mit dem Schlüssel ihrer Firmware signiert sind. Eine Datei unter ihrer eigenen Sicherheitsstufe lehnt sie ab, damit eine alte Firmware mit bekannter Lücke nicht zurückkommt. Unter **Firmware-Plätze** startest du einen älteren Platz. Er muss sich bestätigen wie ein neues Update.

## Releases

Auf der [GitHub-Release-Seite](https://github.com/FusselTV/DeckConnector/releases). Ein Tag `vX.Y.Z` erzeugt ein Release, `vX.Y.Z-rc1` ein Pre-Release.

| Datei | Wofür |
|---|---|
| `deckconnector-factory.bin`, `ota_data_initial.bin`, `deckconnector.bin`, `manifest.json` | Den [Flasher](/de/docs/flashing) und esptool |
| `deckconnector-vX.Y.Z.dbfw`, `deckconnector-web-vX.Y.Z.dbfw` | Signierte Firmware und Weboberfläche. Ein Release ohne Signatur hat keine |
| `deckconnector-matter-vX.Y.Z.dbfw` | Die signierte [Matter-Firmware](/de/docs/matter) |
| `SHA256SUMS` | Prüfsummen aller Dateien |

Einen Download prüfst du mit `sha256sum -c SHA256SUMS --ignore-missing`.

## Weboberfläche

Die Weboberfläche kann sich ohne Firmware-Update ändern und bleibt über Neustarts erhalten. Passt sie nicht zur Firmware, liefert die Platine die eingebaute aus. **Hochgeladene Seite entfernen** geht zu ihr zurück.

## Wiederherstellung über USB

Startet die Platine nicht mehr, flash sie über USB-C. Ein **Update** im [Flasher](/de/flash/) behält die Einstellungen. Der Chip lässt sich nicht unbrauchbar machen, weil sein USB-Lader nicht überschrieben werden kann.

## Selbst signieren

```bash
cd tools
uv run python -m dbtools.dbfw keygen
uv run python -m dbtools.dbfw pack --target p4 --version "$(git describe)" ../firmware/build/deckconnector.bin fw.dbfw
```

`keygen` läuft einmal. Es legt den privaten Schlüssel in `~/.config/deckbridge/ota_key.pem` ab und schreibt den öffentlichen in die Firmware. Ohne den privaten Schlüssel muss die nächste Firmware über USB drauf.
