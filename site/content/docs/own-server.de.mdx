Dein Programm rendert die Bilder. Der Connector hält sie in einem Cache, zeigt sie an und schickt jeden Druck, jede Drehung und jede Berührung zurück. Als Ausgangspunkt dient `tools/dbtools/server.py` im Repository, ein kleiner Python-Host.

## Verbindung

- Der Connector ist der Client. Er öffnet bis zu 2 Hosts mit dem WebSocket-Subprotokoll `deckassistant.v2`.
- Die URLs kommen aus **Quellen**. Solange keine URL eingetragen ist, nimmt er Hosts, die `_deckassistant._tcp` per mDNS anmelden, als `wss://<adresse>:<port>/surface`.
- `ws://` ohne TLS geht nur, wenn du es selbst einträgst. Nimm es für Tests.
- Jede Nachricht ist ein binärer Frame. Text-Frames ignoriert der Connector.
- Der Connector pingt alle 2 s. Ein Host, der 6 s schweigt, gilt als verloren.

## Kopplung

1. Ein Host ohne Token bekommt `HELLO` mit `pairing: true`. Die Decks zeigen einen 6-stelligen Code, 2 min lang über allem, danach auf dem Startbildschirm. Solange ein anderer Host zeichnet, steht der Code nur im Menü. Der Code geht nie über das Netz.
2. Du gibst den Code im Host ein. Der Host schickt `PAIRED` mit einem Token und diesem Code.
3. Passt der Code, speichert der Connector das Token und bei `wss://` den SHA-256 des Zertifikats. Er verbindet sich neu mit `Authorization: Bearer <token>` und nimmt ab dann nur noch dieses Zertifikat.
4. Ein falscher Code bekommt `ERROR` `pair_code`, und der Connector trennt die Verbindung. Nach 5 falschen Codes zeigen die Decks einen neuen.

Kennt ein Host das Token nicht mehr, schließt er mit Code 4001 oder beantwortet den Upgrade mit 401. Der Connector löscht dann das Token und koppelt neu, und nur ein Host mit demselben Zertifikat kommt herein. Eine neue oder gelöschte URL unter **Quellen** löscht Token und Pin. Bis `PAIRED` bekommt jede andere Nachricht `ERROR` `unpaired`.

## Aktiv und Standby

Ein gekoppelter Host fordert die Decks mit `ROLE` 1 an. Der Host, der zuletzt gefragt hat, ist **aktiv**. Er zeichnet auf jedem Deck und bekommt die Eingaben. Der andere steht auf **Standby** und bekommt `ERROR` `standby`, wenn er zeichnet. `ROLE` 0 gibt die Decks zurück.

Solange Companion oder die Elgato-App die gewählte Quelle ist, ist kein Host aktiv. Siehe [Quellen](/de/docs/hosts). Ein Host, der ohne eigenes `ROLE` wieder aktiv wird, bekommt auf derselben Verbindung ein neues `HELLO`. Seine Bilder sind dann vielleicht nicht mehr auf den Decks, also zeichne alle neu.

## Nachrichten

Jede Nachricht beginnt mit 4 Bytes: `u8 type`, `u8 deck` (0 bis 3, `0xFF` für den ganzen Connector), `u16 flags` (0). Zahlen sind Little Endian. CBOR heißt: eine Map mit Text-Schlüsseln. Unbekannte Schlüssel ignorieren beide Seiten.

### Host an Connector

| Typ | Name | Nach dem Header |
|---|---|---|
| `0x01` | ROLE | `u8`: 0 Standby, 1 aktiv |
| `0x02` | PUT | `u16 slot, u8 format, u16 w, u16 h`, dann das Bild. Format 0 JPEG, 1 BMP |
| `0x03` | EVICT | `u16 n`, dann `n` × `u16 slot`. `n = 0xFFFF` leert den Cache |
| `0x04` | FRAME | `u32 frame_id, u16 n`, dann `n` × (`u8 target, u16 slot`). `n` bis 64 |
| `0x05` | STREAM | `u8 target, u32 seq, u8 format`, dann das Bild |
| `0x06` | FALLBACK | `u16 n`, dann `n` × (`u8 target, u16 slot`). `n` bis 64 |
| `0x07` | BRIGHTNESS | `u8` 0 bis 100. Deck `0xFF` stellt jedes Deck |
| `0x08` | TIME | `u64` Unix-Zeit in ms |
| `0x09` | REBOOT | nichts |
| `0x0A` | PAIRED | CBOR `{token, code}`. `token` ist druckbares ASCII, bis 47 Zeichen |

`PUT`, `EVICT`, `FRAME`, `STREAM`, `FALLBACK`, `BRIGHTNESS`, `TIME` und `REBOOT` wirken nur vom aktiven Host. Der Cache gehört dem ganzen Connector, deshalb gehen `PUT` und `EVICT` mit Deck `0xFF`.

### Connector an Host

| Typ | Name | Nach dem Header |
|---|---|---|
| `0x80` | HELLO | CBOR, siehe unten |
| `0x81` | SHOWN | `u8 kind` (0 FRAME, 1 STREAM), `u32 frame_id` bzw. `seq`, `u32` µs bis auf dem Glas |
| `0x82` | CREDIT | `u8 display, u32 bytes, u8 frames` |
| `0x83` | INPUT | `u32 seq, u64 usb_time_us, u8 kind, u8 index, i16 value, u16 x, u16 y, u16 x2, u16 y2` |
| `0x84` | DECK_ADDED | CBOR, ein Eintrag aus `decks` |
| `0x85` | DECK_REMOVED | nichts |
| `0x86` | STATE | CBOR `{display_on, brightness}` |
| `0x87` | ERROR | CBOR `{code, message, id}`. `id` ist die `FRAME`-ID oder `STREAM`-seq, deren `SHOWN` folgt, und nur dort |

## HELLO

```json
{"proto": 2, "firmware": "{{version}}", "board": {"id": "80f1b2a1b2c3", "name": "deckconnector-a1b2c3"},
 "pairing": true, "cache": {"bytes": 8388608, "slots": 1024}, "cache_epoch": 3141592653,
 "decks": [{"deck": 0, "serial": "A00SA0000AA0A0", "model": "streamdeck-plus", "name": "Stream Deck +",
   "displays": [{"id": 0, "w": 800, "h": 480, "formats": ["jpeg"], "rotate": 0, "flip": false, "max_bytes": 1048576}],
   "targets": [{"id": 0, "kind": "key", "display": 0, "x": 13, "y": 12, "w": 120, "h": 120},
               {"id": 8, "kind": "strip", "display": 0, "x": 0, "y": 380, "w": 800, "h": 100},
               {"id": 9, "kind": "full", "display": 0, "x": 0, "y": 0, "w": 800, "h": 480}],
   "keys": 8, "encoders": 4, "touch": [{"x": 0, "y": 380, "w": 800, "h": 100}]}]}
```

- `pairing` gibt es nur vor der Kopplung.
- Ein Tasten-Target hat die Nummer der Taste als `id`. Leisten kommen nach den Tasten, dann das ganze Display (`full`).
- Schick das Bild jedes Targets genau in seiner Größe und schon gedreht. Erst um `rotate` Grad im Uhrzeigersinn drehen, dann links-rechts spiegeln, wenn `flip` wahr ist.
- `formats` ist `jpeg`, beim Mini und beim Module 6 `bmp`. `max_bytes` ist das größte Bild, das das Display nimmt.
- `keys` zählt auch Tasten ohne Bild, etwa die zwei Touch-Tasten des Neo.
- Rechtecke und Touch-Positionen sind Pixel des Displays, Ursprung oben links auf dem ganzen Glas.

Nach `HELLO` kommt ein `CREDIT` pro Display und ein `STATE` pro Deck. `STATE` kommt wieder, wenn der Bildschirmschoner ein Deck aus- oder einschaltet oder sich seine Helligkeit ändert.

Solange der aktive Host verbunden ist, lassen Bildschirmschoner, Bildschirm-Schalter und Helligkeit des Connectors seine Decks in Ruhe, und jede Eingabe erreicht den Host, auch die auf einem dunklen Deck.

## Cache

- Der Connector hält 8 MiB in bis zu 1024 Slots, nummeriert von 0 bis 1023, für alle Decks. Der Host vergibt die Slots und räumt aus. Ein `PUT` in einen belegten Slot ersetzt ihn. Ein Slot lässt sich auf jedem Deck zeigen.
- Ein `PUT`, das nicht passt, bekommt `ERROR` `cache_full`. Ein abgelehntes `PUT` lässt seinen Slot leer.
- `FRAME` zeigt alle seine Slots auf einmal. Beim Plus und Plus XL kommen die Tasten als ein Bild aufs Glas. Andere Decks bekommen einen USB-Transfer pro Taste.
- Wird ein anderer Host aktiv, leert sich der Cache und `cache_epoch` ändert sich. Nach einem Neustart ist es eine neue Zahl. Ein Host, der zurückkommt und die `cache_epoch` wiederfindet, die er kennt, hat seine Slots noch.

## Flusskontrolle

- Jedes `FRAME` und `STREAM` bekommt genau ein `SHOWN`. Kam nichts aufs Glas, ist die Zeit 0 und vorher kommt ein `ERROR`.
- `CREDIT` kommt pro Display nach `HELLO`, `DECK_ADDED` und `ROLE` 1, und wieder, wenn sich der freie Cache um 512 KiB geändert hat. `bytes` ist der freie Platz im Cache. Halte deine `PUT`s darin. `frames` ist, wie viele `FRAME` und `STREAM` dieses Deck vor ihrem `SHOWN` nimmt. Mehr bekommt `ERROR` `busy`.
- Ein neueres Bild für dasselbe Target ersetzt ein wartendes. Dessen `SHOWN` hat dann 0 und kein `ERROR`.
- Solange das Menü des Connectors die Decks verdeckt, kommt `SHOWN` sofort mit 0. Die Bilder erscheinen, wenn das Menü zugeht.

## Video

`STREAM` schickt ein Bild ohne Cache. Schick beim Plus und Plus XL das ganze Display (`full`), bei den anderen Decks einzelne Tasten. Schick eine Taste nur, wenn sie sich geändert hat. Verwirf alte Frames selbst und bleib im `CREDIT`.

## Ausfall-Bild

`FALLBACK` nennt die Bilder für ein Deck, falls die Verbindung zum aktiven Host abreißt. Leg sie früh in Slots. Der Connector zeigt sie dann selbst, bis wieder ein Host zeichnet. Ohne `FALLBACK` zeigt das Deck seinen Startbildschirm.

## Eingaben

| Kind | Name | Felder |
|---|---|---|
| 0 | Taste ab | `index` |
| 1 | Taste auf | `index` |
| 2 | Regler drehen | `index`, `value` in Ticks, positiv im Uhrzeigersinn |
| 3 | Regler ab | `index` |
| 4 | Regler auf | `index` |
| 5 | Touch tippen | `x`, `y` |
| 6 | Touch lang | `x`, `y` |
| 7 | Touch wischen | von `x`, `y` nach `x2`, `y2` |

- `usb_time_us` ist, wann der USB-Report ankam, in µs auf der eigenen Uhr des Connectors. Es ist dieselbe Uhr für jedes Deck, und sie läuft nur vorwärts. `TIME` ändert sie nicht.
- `seq` zählt pro Verbindung hoch. Eine Lücke heißt, eine Eingabe ging verloren.
- Verwirf `INPUT`, dessen `usb_time_us` mehr als 1 s älter ist als das neueste, das du gesehen hast, und stell Aktionen nie in eine Warteschlange. Ein verspätet geschaltetes Schloss ist schlimmer als ein verlorener Druck.

## Fehler

| `code` | Bedeutung |
|---|---|
| `unpaired` | Bis zur Kopplung nur `PAIRED` schicken |
| `pair_code` | Nicht der Code, den die Decks zeigen. Der Connector trennt |
| `pair_failed` | Der Connector konnte die Kopplung nicht speichern und trennt |
| `standby` | Dieser Host ist nicht aktiv |
| `no_deck` | Kein Deck mit dieser Nummer |
| `bad_target` | Kein Target mit dieser Nummer |
| `empty_slot` | Dieser Slot ist leer |
| `bad_size` | `w` und `h` des Slots passen nicht zum Target |
| `bad_format` | Das Display nimmt dieses Format nicht |
| `bad_slot` | Slot 1024 oder höher |
| `cache_full` | Das `PUT` passt nicht in den Cache |
| `busy` | Mehr als `CREDIT` erlaubt, oder dem Connector fehlt Speicher |
| `too_big` | Größer als `max_bytes` des Displays |
| `not_drawing` | Der eigene Bildschirm des Connectors hat das Deck inzwischen übernommen |
| `bad_message` | Falsche Länge oder mehr als 64 Paare |
| `unknown_type` | Unbekannter Nachrichtentyp |
