The board takes signed `.dbfw` files. Each file holds one part, and the board sees which part it is.

| Part | After the update |
|---|---|
| Firmware | Goes into the next slot, the board restarts into it |
| Wi-Fi chip | Both chips restart |
| Web page | Served at once |
| Bootloader, partition table | Written in place, no restart |

## Install

- In the web UI under **Firmware** ([demo](/demo/#firmware)), pick a file or give an `http://` URL.
- From your [own server](/docs/own-server), send `{"t": "ota", "url": "http://..."}`.
- Over the [API](/docs/api#firmware), `POST /api/ota` with the file, or `POST /api/ota/url`.

## Checks and rollback

<OtaFlow />

A board takes only files signed with the key its firmware was built with. It refuses a file below its own security level, so an old firmware with a known hole cannot come back. Under **Firmware slots (advanced)** you can start an older slot. It must confirm itself like a new update.

## Releases

On the [GitHub releases page](https://github.com/FusselTV/deck-connector/releases). A tag `vX.Y.Z` makes a release, `vX.Y.Z-rc1` a pre-release.

| File | Use |
|---|---|
| `deckconnector-factory.bin`, `ota_data_initial.bin`, `deckconnector.bin`, `manifest.json` | The [flasher](/docs/flashing) and esptool |
| `deckconnector-vX.Y.Z.dbfw`, `deckconnector-web-vX.Y.Z.dbfw` | Signed firmware and web page. A release without signing has none |
| `SHA256SUMS` | Checksums of all files |

Check a download with `sha256sum -c SHA256SUMS --ignore-missing`.

## Web page

The web page can change without a firmware update and stays over restarts. When it does not fit the firmware, the board serves the page built into its firmware. **Remove uploaded web interface** goes back to that page.

## Recovery over USB

When the board no longer starts, flash it over USB-C. An **Update** in the [flasher](/flash/) keeps the settings. The chip cannot be bricked, because its USB loader cannot be overwritten.

## Sign your own

```bash
cd tools
uv run python -m dbtools.dbfw keygen
uv run python -m dbtools.dbfw pack --target p4 --version "$(git describe)" ../firmware/build/deckconnector.bin fw.dbfw
```

`keygen` runs once. It keeps the private key in `~/.config/deckbridge/ota_key.pem` and writes the public key into the firmware. Without the private key, the next firmware goes on over USB.
