The connector takes signed `.dbfw` files. Each file holds one part, and the connector sees which part it is.

| Part | After the update |
|---|---|
| Firmware | Goes into the next slot, the connector restarts into it |
| Wi-Fi chip | Both chips restart |
| Web page | Served at once |
| Bootloader, partition table | Written in place, no restart |

## Install

- In the web UI under **Firmware** ([demo](/demo/#firmware)), pick a file or give an `http://` URL.
- From your [own server](/docs/own-server), send `{"t": "ota", "url": "http://..."}`.
- Over the [API](/docs/api#firmware), `POST /api/ota` with the file, or `POST /api/ota/url`.

## Checks and rollback

<OtaFlow />

A connector takes only files signed with the key its firmware was built with. It refuses a file below its own security level, so an old firmware with a known hole cannot come back. Under **Firmware slots** you can start an older slot. It must confirm itself like a new update.

## Releases

On the [GitHub releases page](https://github.com/FusselTV/DeckConnector/releases).

| File | Use |
|---|---|
| `deckconnector-factory.bin`, `ota_data_initial.bin`, `deckconnector.bin`, `manifest.json` | The [flasher](/docs/flashing) and esptool |
| `deckconnector-vX.Y.Z.dbfw`, `deckconnector-web-vX.Y.Z.dbfw` | Signed firmware and web page. A release without signing has none |
| `deckconnector-matter-vX.Y.Z.dbfw` | The signed [Matter firmware](/docs/matter) |
| `SHA256SUMS` | Checksums of all files |

Check a download with `sha256sum -c SHA256SUMS --ignore-missing`.

## Web page

The web page can change without a firmware update and stays over restarts. When it does not fit the firmware, the connector serves the page built into its firmware. **Remove uploaded page** goes back to that page.

## Recovery over USB

When the connector no longer starts, flash it over USB-C. An **Update** in the [flasher](/flash/) keeps the settings. The chip cannot be bricked, because its USB loader cannot be overwritten.
